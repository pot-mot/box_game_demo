# 箱庭游玩模式设计总览

> 本目录记录「箱庭游玩模式」的完整设计。代码实现以本文档为准；实现完成后同步更新 `AGENTS.md`。

## 1. 目标

在现有 `play` 模式之上叠加一套完整的箱庭（hakoniwa）游玩体验：

1. **箱庭生成器** —— 一键产生宏伟建筑式箱庭（体素 + terrain 配合），呈现类似洛斯里克城 / 史东薇尔城 / 幽影城 / 劳弗古遗迹的巨构箱庭。
2. **交互系统** —— play 模式默认 `F` 键的交互状态与交互骨骼动画；edit 模式可主动触发物体交互。
3. **交互物子系统** —— 存档点、传送点、开关、单推门、双推门、垂直升降闸门、箱子（容器）、升降梯、可攻击/翻滚破坏的场景道具。
4. **背包与物品子系统** —— 存档持久化、物品掉落、物品拾取、俄罗斯方块式格子背包 UI。
5. **装备子系统** —— 面向玩家的装备 GUI：玩家模型展示 + 环绕式装备槽，与物品子系统互通。
6. **地图与传送点子系统**，以及**脱困子系统**。
7. **建筑结构子系统** —— 基于 `building_generator` 的楼梯、旋转楼梯、斗拱、斜屋顶、走道/廊桥、支柱。

## 2. 集成策略（已定）

- **不新增 `GameMode`**：启动屏「游玩模式」即箱庭游玩模式。`GAME_MODE_VALUES` 保持不变，避免改动输入模式映射、`main.ts` 模式分派与 `modeInfo` 序列化分支。
- 新增子系统在 **`setupPlayMode`** 内装配，其 `updater` 串接在现有顺序中。
- 需要跨系统访问的依赖由 `main.ts` 传入：`systems: EntityInfoSource[]`、`building: BuildingGeneratorContext`，以及新注册的交互物系统。
- 单 RAF 约束不变：所有子系统返回 `(dt: number) => void`，由 `playMode.updater` 统一调用。

## 4. 依赖方向

- `character/`（含 `character/interaction/`）为独立领域层，**不依赖 `entity/`**；`entity/` 依赖 `character/`。
- `inventory/` 为独立领域层，不依赖 `entity/` / `modes/`。
- `entity/interactable/` 可依赖 `inventory/`（容器/掉落的物品数据）与 `character/interaction/`。
- `modes/play/*` 依赖所有下层，负责装配与 UI。
- `entity/*` 之间不相互引用；交互物与掉落物通过 `main.ts` 注册进 `systems` 数组，避免直接互相 import。

## 5. 全局约定

1. **输入动作**：交互 `interact`（默认 `KeyF`）；背包 `open_inventory`（默认 `KeyB`）；装备 `open_equipment`（默认 `KeyE`）；地图 `open_map`（默认 `KeyM`）。脱困不设快捷键，改为右上角设置菜单「传送至最近存档点」。新增动作必须同步 `INPUT_ACTIONS` / `ACTION_LABELS` / `ACTION_GROUPS` / `DEFAULT_BINDINGS` / `registry.test.ts` 的 `EXPECTED_DEFAULTS`。
2. **类型系统**：禁 `any` / `enum` / `export default`；`import type`；路径带 `.ts`；4 空格缩进；注释中文；常量集中到各分包 `constants.ts`。
3. **存档**：`SAVE_FORMAT_VERSION` 每引入一类新持久数据 +1；全部新字段可选且校验层 `.optional().catch(...)` 安全回退，未知 id 在领域层丢弃，绝不抛错。
4. **性能**：帧内复用向量与临时对象；交互物/掉落物数量有限，每帧解析避免分配。
5. **碰撞类别**：新增碰撞体必须 `categoryCollisionGroups` 标注 `interactable` / `item`（在 `collision_category.ts` 新增位），否则 fail-closed 被判为 `ground`。
6. **id 命名**：交互物内部键 `ix:{entityId}:{index}` 或 `kind` 唯一字符串；物品 id 用小写下划线。
