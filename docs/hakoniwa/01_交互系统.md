# P1 交互系统

交互系统是箱庭游玩的基础：玩家按 `F` 对最近的可交互物执行一次交互动作（含骨骼动画），edit 模式可主动触发。

## 1. 输入动作

在 `src/input/types.ts` 的 `INPUT_ACTIONS` 增加 `'interact'`，并同步：

- `ACTION_LABELS.interact = '交互'`
- `ACTION_GROUPS` 的「角色」组加入 `'interact'`
- `src/input/constants.ts` 的 `DEFAULT_BINDINGS` 增加 `interact: [['KeyF']]`（`CODE_LABELS` 已含 `KeyF`）
- `src/input/registry.test.ts` 的 `EXPECTED_DEFAULTS` 增加同名条目

读取方式：`input.wasActionPressed('interact') && input.isActionActive('interact')`（后者防止被更长组合遮蔽，参照 `cycle_hold_mode`）。

## 2. 交互领域模型（`src/character/interaction/`）

纯类型层，**不依赖 `entity/`**，供角色状态机与实体实现共同引用。

`types.ts`：

```ts
/** 交互目标：由交互物实体构造的只读描述，字符领域只读取位置 / 提示 / 可用性 */
export interface InteractionTarget {
    /** 全局唯一键（如 `interactable:12:0`），play 侧据它维护激活回调 */
    readonly key: string
    /** 交互物类型（用于文案/图标，取值见 entity/interactable/kinds.ts） */
    readonly kind: string
    /** 交互提示文案，如「点燃篝火」「开启」「拾取」 */
    readonly prompt: string
    /** 目标世界坐标（评分与转身朝向） */
    readonly x: number
    readonly y: number
    readonly z: number
    /** 距离评分（越小越优先），由提供方计算 */
    readonly score: number
}

/** 交互物提供者：交互物 / 掉落物系统实现，play 侧汇总候选 */
export interface InteractionProvider {
    /** 收集候选交互目标；out 复用数组，返回收集个数 */
    collectInteractionTargets: (actorX: number, actorY: number, actorZ: number, out: InteractionTarget[]) => number
}

/** 交互动作总时长（秒），与 `interactingPose` 的 clip 时长一致 */
export const INTERACTION_DURATION = 0.9
/** 交互生效时刻（秒，动作进度 50%），在此触发实际效果 */
export const INTERACTION_ACTIVATE_TIME = 0.45
/** 候选交互最大距离（米），超出不显示提示 */
export const INTERACTION_MAX_DISTANCE = 2.4
/** 候选交互的最大镜头偏角余弦阈值（约 70°） */
export const INTERACTION_MAX_ANGLE_COS = 0.34
```

`index.ts` 统一 re-export。

## 3. 状态机

### 3.1 类型

`src/character/state_machine/types.ts`：

- `CHARACTER_STATES` 增加 `'interacting'`。
- `CharacterInput` 增加 `interact: boolean`（脉冲）。
- `CharacterStateMachine.setInput` 增加末位参数 `interact?: boolean`。

### 3.2 角色实体瞬态字段

`src/character/types.ts` 的 `CharacterEntity` 增加：

```ts
/** 本帧是否有可交互目标（由 world.ts 按玩家交互脉冲写入；用于交互转换守卫） */
interactTargetActive: boolean
/** 交互目标世界坐标（转身朝向用；无目标时保持上次值即可） */
interactTargetX: number
interactTargetZ: number
```

### 3.3 状态文件 `states/interacting.ts`

- `enter`：将水平速度清零（交互时站定），锁定朝向（由 `world.ts` 的朝向逻辑处理）。
- `update`：仅做减速（若被外力推动），不响应移动输入。
- `exit`：不额外处理。
- `transitions`：
  - `to: 'flinching'`（受击打断，沿用 flinching 的守卫条件）
  - `to: 'dying'`
  - `to: 'idle'` / `to: 'walking'`：`ctx.stateTime >= INTERACTION_DURATION`（交互完成后按是否有移动输入回到 idle/walking）

`idle.ts` / `walking.ts` 增加 `to: 'interacting'`，守卫：

```ts
guard: (input, entity) => input.interact && entity.interactTargetActive
```

**顺序**：`interacting` 转换必须排在 `jumping` 之前（交互优先于跳跃），且 `walking` 中排在 `to: 'idle'` 之前。

`machine.ts`：

- `input` 初始化与 `reset` 增加 `interact = false`。
- `setInput` 写入 `input.interact = interact ?? false`。
- `STATE_HANDLERS` 注册 `interacting: interactingHandler`。

### 3.4 输入注入（`entity/character/physics/world.ts`）

- 模块变量：`let playerInteractPending = false`、`playerInteractTargetX/Z = 0`。
- 接口新增：
  ```ts
  setPlayerInteract: (pending: boolean, targetX: number, targetZ: number) => void
  ```
- 玩家分支在 `stateMachine.setInput(...)` 末尾传 `playerInteractPending`，并在调用前写入实体字段：
  ```ts
  entity.interactTargetActive = playerInteractPending
  if (playerInteractPending) { entity.interactTargetX = playerInteractTargetX; entity.interactTargetZ = playerInteractTargetZ }
  ```
- 帧末与 `playerAttackPending` 一同清零 `playerInteractPending`。
- 朝向逻辑：新增分支——玩家处于 `interacting` 且 `interactTargetActive` 时，
  `targetAngle = atan2(interactTargetX - posX, interactTargetZ - posZ)`。

## 4. 骨骼动画

### 4.1 程序化姿态（`src/entity/character/appearance/pose_fns.ts`）

新增 `interactingPose(t, ctx)`：一个「伸手（0→0.45s）— 发力/下压（0.45→0.9s）」的非循环姿态。默认右臂前伸、躯干微前倾、膝盖微屈；持械时保持器械朝前臂外侧（不强制）。实现时复用文件内已有的关节常量与 `ZERO`，并在 `BASE_POSE_SAMPLERS` 与 `BASE_CLIP_META` 登记：

```ts
interacting: {duration: INTERACTION_DURATION, loop: false}
```

`PoseSampler` 的 key 联合类型会自动扩展，`getBaseClipForHoldMode` / `getBaseLayers` 随之支持。

### 4.2 外观系统（`src/entity/character/appearance/system.ts`）

- `CLIP_STATES` 与 `ClipState` 增加 `'interacting'`。
- 无需特殊分支，走基础 clip 单层播放。

> `adjustArmsForHoldMode` 仅对 idle/walking 生效，交互动画不受持握模式影响（有意：交互动作为通用伸手）。

## 5. 交互目标解析（play）

新增 `src/modes/play/interaction/`：

### 5.1 `resolve.ts`

```ts
export interface ResolvedInteraction {
    target: InteractionTarget
    activate: () => void
}
```

- 维护 `providers: InteractionProvider[]` 与 `activators: Map<string, () => void>`。
- `resolveInteraction(actor, cameraDir)`：
  1. 对每个 provider 调用 `collectInteractionTargets` 收集候选（复用数组避免分配）；
  2. 过滤 `score <= INTERACTION_MAX_DISTANCE`；
  3. 按「距离 + 镜头偏角」排序取最优（复用 `lock_on.ts` 的评分思路）；
  4. 返回该目标的 `activate` 回调。
- provider 由 `main.ts` 在装配时注册（交互物 / 掉落物系统各自实现 `InteractionProvider`）。

### 5.2 `prompt.ts`

- 屏幕中下方的固定 DOM 提示条：「`[F]` + 提示文案」。
- 每帧 `update(target | undefined)` 脏检查，无目标时 `display:none`。
- 面板销毁时移除 DOM。

### 5.3 `index.ts`

```ts
export interface PlayInteractionController {
    update: (dt: number, actor: CharacterEntity | undefined, camera: PerspectiveCamera) => void
    registerProvider: (provider: InteractionProvider) => void
    registerActivator: (key: string, activate: () => void) => void
    dispose: () => void
}
```

每帧流程：

1. 若上一帧进入 `interacting`，则递增本地 `activationTimer`；当 `>= INTERACTION_ACTIVATE_TIME` 且未触发时调用当前 `pendingActivate()`（由 `interactables.activate` 提供），随后置 `fired`。
2. 解析当前目标并刷新提示：交互进行中时保持显示原目标提示，否则显示解析结果。
3. 若玩家按 `F` 且存在目标：调用 `characterSystem.setPlayerInteract(true, target.x, target.z)`，记录 `pendingTarget`、`activationTimer = 0`、`fired = false`。
4. 若玩家离开 `interacting`：清理 `pendingTarget`。

> 状态机负责拒绝非法时机的交互（如翻滚/攻击中），play 侧只在观察到真实进入 `interacting` 后计时触发效果。

## 6. edit 主动触发

- 交互物面板（`entity/interactable/ui/panel.ts`）在选中交互物时提供「触发交互」按钮，调用 `ctx.activate(id)` 直接激活（跳过玩家动画）。
- 也可为 edit 模式绑定 `interact` 动作触发**当前选中**的交互物：在 `setupEditMode` 中 `input.onActionDown('interact', ...)`，对 `interactables.getSelected()` 调用激活。文档以此为准，实现时二者都做（按钮 + 快捷键）。

## 7. 装配接线

- `main.ts`：在实体系统初始化区新增 `const interactables = setupInteractables(scene, shared, ...)`，加入 `systems` 与 `bodyProviders`，并在 `setupPlayMode(...)` 参数中传入。
- `setupPlayMode` 新增参数：`systems: EntityInfoSource[]`、`building: BuildingGeneratorContext`、`interactables: InteractableContext`。
- `playMode.updater` 顺序追加：`interaction.update(dt, player, camera)`（在 `characterSystem.update` 之后、相机更新之前或之后均可，以提示与激活为准）。
