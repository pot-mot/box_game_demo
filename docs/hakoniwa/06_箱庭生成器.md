# P6 箱庭生成器与建筑结构

目标：在现有 `building_generator`（体素 chunk + 贪心网格 + trimesh 物理 + 自由道具）之上，提供楼梯、旋转楼梯、斗拱、斜屋顶、走道/廊桥、支柱等建筑结构，并能一键产生宏伟建筑式箱庭。

## 1. 结构原语（`generators/architecture.ts`）

`BlockWriter` 只有轴对齐 `set/clear`，因此所有旋转/镜像在结构函数内部做坐标变换。新增统一定向辅助：

```ts
/** 将局部 (x,z) 绕原点顺时针旋转 q*90°，返回 [x,z] */
export const rotateQuarter = (x: number, z: number, q: number): [number, number]
/** 按方向写入（dir: 0=+X,1=+Z,2=-X,3=-Z），把局部 (u=前进, v=侧向) 映射到世界轴 */
export const dirAxis = (dir: number): {ux:number; uz:number; vx:number; vz:number}
```

结构函数（全部接收 `writer, origin[3], ...`, 只写局部体素）：

```ts
export const stairs = (writer, ox,oy,oz, dir, steps, width, material): void
export const spiralStairs = (writer, ox,oy,oz, radius, totalRise, material): void
export const pillar = (writer, ox,oy,oz, height, material, thick = 1): void
export const dougong = (writer, ox,oy,oz, material): void          // 斗拱：柱顶 3×3 交错木构
export const pitchedRoof = (writer, ox,oy,oz, sizeX, sizeZ, height, material, ridgeAxis): void
export const corridor = (writer, x0,z0, x1,z1, y, width, material, railing = true): void
export const archGate = (writer, ox,oy,oz, dir, width, height, material): void
export const floorSlab = (writer, ox,oy,oz, sizeX, sizeZ, material): void
```

要点：
- `stairs`：每步 `rise=1`，`run` 由参数决定（默认 1）；支撑立面填实或镂空。
- `spiralStairs`：极坐标逐格落体素，半径按高度增大，中央可留柱。
- `dougong`：以交叉叠涩表达斗拱（横拱 + 升 + 昂），可用于檐下连续排布。
- `pitchedRoof`：双坡屋顶，沿 `ridgeAxis` 收拢，檐口比墙体多出 1 格（飞檐）。
- `corridor`：在两点间生成水平走道（曼哈顿折线），可带两侧栏杆/支柱；跨沟壑时自动在下方补支柱至地面（地面高度由调用方给定）。

## 2. 配方登记（`generators/structures.ts`）

在既有 `house/tower/wall/platform/ruin/tree` 之外新增：

| recipe | 内容 |
|--------|------|
| `stairs` | 直跑楼梯 |
| `spiral_stairs` | 旋转楼梯塔 |
| `bridge` | 廊桥（两端门洞 + 栏杆 + 支柱） |
| `great_hall` | 大殿：台基 + 柱列 + 斗拱檐 + 斜屋顶 + 门洞 |
| `keep` | 主楼：多层楼板 + 螺旋梯 + 四角塔 + 斜屋顶 |
| `garden` | **顶层箱庭**：64³ 内容纳台地、主楼、角塔、连廊、庭院、外墙、牌楼、树石点缀 |

`generateBuilding` 保持「未知配方回退 house」。新配方自动出现在编辑面板与笔刷下拉。

## 3. 一键箱庭

当前实现：`garden` 顶层配方即「一键箱庭」——在固定 40×40 布局内生成台地、外墙（带垛口）、四角塔、中央主楼（含螺旋梯与斜屋顶）、四向连廊、庭院斗拱灯台等，显著大于既有 `house` / `keep`。编辑模式选中「Building」生成类型右键放置即为 `house`，如需 `garden` 可在建筑面板把配方改为 `garden` 或直接用笔刷预制体（`stamp`）选择 `garden`。

**未实现（后续扩展）**：`generateHakoniwa()` 多世界编排函数与「生成期交互物标记」机制（`BlockWriter.marker` + `BuildingGeneratorHooks.onMarkers`）。交互物目前由编辑模式手动放置并随其自身存档持久化。

## 4. 物理与性能

- 大体量生成会让上千 chunk 变脏；渲染/物理每帧分别最多重建 `4`/`2` 个 chunk（`constants.ts`）。生成后首次可见会有数秒渐次构建，属既有摊还机制，不新增旁路。
- 生成器写入不走 `MAX_FILL_BLOCKS` 限制（该限制仅交互式区域工具）。
- 静态建筑不参与物理步进，可见性由 `building.updateView` 维护。

## 5. 存档与兼容

- 生成器代码版本与存档解耦：存档只存显式体素（palette + RLE），配方变更不影响旧档。
- 交互物落点不随建筑存档保存；建筑存档加载后，交互物以其自身存档条目恢复。

## 6. 测试

- `generators/architecture.test.ts`：楼梯每级高度递增、旋转楼梯覆盖行程、斜屋顶檐口外扩、廊桥两端连通且落支柱、斗拱/支柱实心、地台填满、`rotateQuarter` 四方向。
- 顶层配方（`garden` / `great_hall` / `keep` 等）由编辑模式 e2e 与手动验证覆盖；生成器确定性由 `createRng` 保证。
